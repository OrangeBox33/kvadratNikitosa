# tools/ — картинки, чат и боты для LED-панели

Всё в этой папке общается с сервером **как обычный браузерный клиент**: подключается
к `wss://kvadratnikitosa.ru` и шлёт те же самые сообщения, что и сайт —
`{ type: 'draw', pixels: [{ id, color }] }` при рисовании и
`{ type: 'sendToChat', chatMessage: { username, text } }` в чат. Текущее состояние
(сетку и чат) сервер присылает сам первыми двумя сообщениями после подключения —
запрашивать ничего не надо.

**Сервер ради этого не менялся и меняться не должен.** Он сам обновит авторитетный
`grid`, запишет кадр в `history`, разошлёт пиксели остальным браузерам и запушит
бинарь на все панели (с делением яркости на 4 и serpentine-ремапом).

Запускается без сборки и без npm-зависимостей: plain `.mjs` + встроенный в Node 22
`WebSocket`, картинки декодирует системный `sips` (macOS).

## Команды

```bash
# Бот-художник (картинка раз в 10 минут + название в чат)
./tools/kvadrat-random.sh now       # ← основная ручка: обновить картинку СЕЙЧАС, без лока
./tools/kvadrat-random.sh           # цикл раз в 10 минут (под локом)
./tools/kvadrat-random.sh once      # один прогон под локом — для cron
nohup ./tools/kvadrat-random.sh >/dev/null 2>&1 &   # цикл в фоне
KVADRAT_DRY=1 ./tools/kvadrat-random.sh now         # придумать, но не отправлять

# Бот-посетитель (реплика в чат раз в 4 минуты)
./tools/kvadrat-visitor.sh now      # одна реплика прямо сейчас, без лока
./tools/kvadrat-visitor.sh          # цикл раз в 4 минуты (под локом)
./tools/kvadrat-visitor.sh once     # один прогон под локом — для cron
nohup ./tools/kvadrat-visitor.sh >/dev/null 2>&1 &  # цикл в фоне
KVADRAT_DRY=1 ./tools/kvadrat-visitor.sh now        # придумать реплику, но не отправлять

# Чат и состояние
./tools/kvadrat-say.mjs --user Гоша "Похоже на кактус"
./tools/kvadrat-state.mjs           # цветное превью панели + последние сообщения
./tools/kvadrat-state.mjs --art     # то же машиночитаемо: палитра + 16 строк + CHAT:

# Готовая сетка
./tools/kvadrat-send.mjs grid.txt
echo "$GRID" | ./tools/kvadrat-send.mjs --quiet
./tools/kvadrat-send.mjs --clear

# Картинка
./tools/kvadrat-image.mjs photo.jpg
./tools/kvadrat-image.mjs photo.jpg --preview --gamma 1.4
./tools/kvadrat-image.mjs https://…/pic.png --fit contain
```

## Как работает бот-художник

1. **Бросает кубик**: выбирает жанр композиции (10 вариантов) и настроение палитры (6),
   и жёстко задаёт их в промпте. Разнообразие приходит из скрипта, а не от модели — см.
   ниже, почему это принципиально. Зерно из `/dev/urandom` и список прошлых тем тоже в промпте.
2. Запускает `claude -p --model $KVADRAT_MODEL --output-format text` **из `/tmp`** — иначе CLI
   подхватил бы `CLAUDE.md` проекта и тащил его в контекст каждый тик.
3. Модель отвечает строго в формате:

   ```
   TITLE: Тюбик зубной пасты
   PALETTE: .=#000000 A=#ff0000 B=#ffffff
   GRID:
   <16 строк по 16 символов>
   ```

4. `kvadrat-send.mjs` парсит это и шлёт на панель. `TITLE` идёт в лог, в файл тем
   и **в чат** через `kvadrat-say.mjs` — на панели видна только картинка, подпись
   к ней живёт на сайте.
5. В чат пишем **после** успешной отправки картинки и отдельным подключением, чтобы
   подпись не опередила рисунок. Если чат не ответил, тик всё равно считается удачным:
   картинка уже на панели.
6. В терминале видно две строки: `Придумываю картинку (обычно 20-60с)...` и `Отправлено: [название]`.
   При запуске не из терминала (cron, nohup) не печатается ничего — проверка `[ -t 2 ]`.

Один тик — **1–2 минуты** (в основном старт CLI). Это нормально, не зависание.

### Почему жанр выбирает скрипт, а не модель

Первые 43 картинки бота — **все до одной** «один бытовой предмет крупным планом»: вантуз,
штопор, домкрат, огнетушитель, мясорубка. Причин было четыре, и все в промпте:

1. «силуэт должен читаться в 16×16» — прямое требование одного читаемого силуэта;
2. «фон чёрный #000000» в жёстких ограничениях — композиция «предмет на пустоте» задана заранее;
3. чёрный список «не сердечко, не смайл, не гриб, не звезда, не котик, не ёлка» вычеркнул
   ровно живое и нефигуративное, оставив предметы;
4. **список прошлых тем работал как few-shot-примеры**: пятнадцать бытовых предметов подряд —
   лучшая инструкция «дай шестнадцатый». Чем дольше бот работал, тем сильнее себя запирал.

Вывод, ради которого всё и переписано: **просить модель «быть разнообразнее» бесполезно** —
она выдаёт своё среднее представление о неожиданном, и оно всегда одно. Поэтому жанр и палитру
бросает скрипт (`GENRE_KEYS`/`GENRE_TEXTS`/`PALETTE_TEXTS`), а модель придумывает сюжет уже
внутри рамки. Жанры: `object` (прежнее поведение, теперь 1 из 10), `tiny`, `landscape`, `stick`,
`scene`, `abstract`, `pattern`, `macro`, `sign`, `invert`.

Два момента:

- **Последние 3 жанра исключаются из броска.** Честный кубик спокойно выдаёт три пейзажа подряд —
  ровно ту однообразность, от которой уходили. Жанр пишется в файл тем первым полем.
- **Жанр `invert` зажигает все 256 диодов.** Обычная картинка — это десяток-другой светящихся
  пикселей (~0.5 A), заливка светлым фоном при делении яркости на 4 — примерно 3.5–4 A на панель.
  Ограничения на яркость фона в промпте нет сознательно; если блок питания начнёт проседать,
  убирать надо здесь.

## Как работает бот-посетитель

Идея: фестиваль, мимо панели ходят люди, кто-то останавливается, смотрит на картинку,
цепляет взглядом чат и бросает реплику на ходу. Каждый тик — **новый человек**: своё имя,
своя манера речи и **никакой памяти** о прошлых тиках.

1. `kvadrat-state.mjs --art` одним подключением забирает и картинку, и чат:

   ```
   PALETTE: .=#000000 A=#ffff00 B=#00ffff C=#ffaa00
   GRID:
   <16 строк по 16 символов>
   CHAT:
   грибочек: мяу
   художник: Заряженная батарейка
   ```

   Символьная сетка — это `gridToArt()`, обратная операция к `parseGrid()`. Модель
   читает картинку в том же виде, в каком сама её рисует; ANSI-превью ей бесполезно.
2. **Бросается кубик манеры** — 12 вариантов, от возгласа до смайлика (см. ниже).
   Блок состояния, манера и зерно из `/dev/urandom` вклеиваются в промпт. Больше
   в промпте нет ничего: ни прошлых реплик, ни тем.
3. Модель отвечает двумя строками:

   ```
   NAME: Гоша
   TEXT: Робот с усами, стопудово
   ```

4. `kvadrat-say.mjs` шлёт это в чат. Ничего не рисует — панели бот не касается.

### Манера речи — тоже кубик

Манеру бросает скрипт (`STYLE_KEYS`/`STYLE_TEXTS`), по той же причине, что и жанр
у художника: просьба «говори разнообразно» даёт среднее представление модели о
разнообразии, и все посетители выходят на одно лицо. Двенадцать манер:

`shout` (КРУТО!) · `question` · `guess` (догадка) · `sentence` (обычное предложение
на 5–10 слов) · `grumble` (беззлобно поворчать) · `emoji` (только смайлик, без слов) ·
`deadpan` (сухая констатация) · `praise` · `reply` (ответить кому-то из чата по имени) ·
`request` (попросить нарисовать) · `offtop` (про фестиваль, очередь, кофе) · `joke`.

**Длина теперь часть манеры, а не общее правило.** Раньше в промпте трижды стояло
«2–4 слова» — из-за этого все реплики были одинаково куцые. Возглас — одно слово,
рассказчику нужно предложение; каждая манера несёт свою длину.

Тринадцатая манера, `answer`, живёт **вне кубика**: она включается, только если
последняя реплика в чате заканчивается вопросительным знаком, и тогда с вероятностью
`ANSWER_CHANCE` (7 из 10) посетитель отвечает именно на этот вопрос. Не 10 из 10
сознательно — живой зал иногда пропускает вопрос мимо ушей. Поэтому манеру выбираем
уже **после** чтения чата, а не до.

### Почему прошлых реплик в промпте нет

Раньше в промпт уходили последние 10 сказанных фраз («не повторяйся»), и получалось
ровно наоборот: посетители сутками обсуждали ромб, которого на панели давно не было —
список работал не как запрет, а как тема для разговора.

Теперь единственная память — **сам чат**, который сервер отдаёт при подключении.
Но и он отстаёт от картинки (6 сообщений живут дольше, чем одна картинка), поэтому
в промпте отдельным абзацем сказано: панель важнее чата, и тему, которой на панели
уже нет, подхватывать не надо.

Жёсткой защиты от повторов нет сознательно: похожие реплики в живом чате — норма,
а пропущенный из-за них тик означал бы четыре минуты тишины.

### Ограничения чата, о которых надо помнить

- Сервер держит всего **6 последних сообщений** (`CHAT_SIZE = 5`, лишнее выталкивается),
  поэтому посетитель всегда видит только свежий разговор — это и есть «зашёл на минуту».
- `username` режется до 16 символов, текст — до 150 (`server/constants.ts`); `lib/kvadrat.mjs`
  режет их на своей стороне, чтобы отправить ровно то, что потом увидим в чате.
- **`username === text` — это не сообщение, а команда серверу**: `42` проигрывает историю
  на панелях, `228` её стирает; в чат такое не попадает вовсе. `sendChat()` отказывается
  слать такие пары, а бот-посетитель дополнительно отбрасывает тик, если модель выдала
  имя, совпавшее с репликой.

### Форматы входа `kvadrat-send.mjs`

1. **256 hex-цветов** через любые разделители (`#ff0000 #00ff00 …`).
2. **Палитра + сетка** — то, чем отвечает модель: строки `A=#RRGGBB` в любом месте текста,
   плюс 16 строк ровно по 16 символов. Символы `.` и пробел всегда чёрные.

Всё, что не похоже на палитру или строку сетки, игнорируется — болтовня вокруг данных не мешает.
Если модель забыла объявить символ, работает мягкий проход: неизвестные символы становятся фоном.

## Грабли, на которые уже наступили

Это самое ценное в файле — все четыре стоили отладки:

1. **`--disallowed-tools` у `claude` — variadic-флаг.** Позиционный промпт после него
   разбирается как продолжение списка инструментов (`Permission deny rule "Придумай" matches
   no known tool`). Решение: промпт подаётся через **stdin** (`<"$prompt"`).
2. **Командная подстановка + фоновый watchdog = вечное зависание.** `answer=$(ask_claude ...)`
   ждёт закрытия пайпа всеми процессами, а `( sleep 180; kill )&` его унаследовал — каждый тик
   висел ровно 184 секунды. Решения сразу три: watchdog пишет в `/dev/null`, его `sleep`
   добивается через `pkill -P` (kill подшелла сам `sleep` не убивает), а путь к ответу
   передаётся переменной `ANSWER_FILE`, а не через stdout.
3. **bash 3.2 из macOS не понимает UTF-8 в раскрытии переменных.** `${title:-без названия}`
   и `«$title»` падают с `unbound variable`: многобайтный символ считается частью имени
   переменной. Поэтому в скрипте нет ёлочек и нет русских дефолтов в `${…:-…}`.
4. **Лок пережил жёстко убитый процесс.** Каталог-лок остался после закрытой консоли, и все
   запуски молча выходили. Теперь в лок пишется pid, мёртвый владелец не блокирует — лок забирается.
   Плюс `disown` для watchdog, иначе bash печатал `Terminated: 15 ( sleep … )`.

Служебные файлы: локи `$TMPDIR/kvadrat-random.lock` и `$TMPDIR/kvadrat-visitor.lock`
(внутри `pid`), логи и списки тем/реплик там же. Локи у ботов **разные** — художник
и посетитель работают независимо и могут крутиться одновременно.
Если что-то пошло не так — `rm -rf "$TMPDIR/kvadrat-*.lock"` и смотреть лог.

## Что можно сделать дальше

- **Фото на 16×16 разваливается**, если объект мелкий: сейчас есть `--offset` (сдвиг квадрата),
  но нет зума. Просилось `--zoom N` или `--crop W,H,X,Y`; пока это делается двумя шагами
  через `sips -c 260 260 --cropOffset 20 170 photo.avif -s format png --out /tmp/head.png`
  (порядок offset — `Y X`).
- **Автозапуск ботов**: сейчас `nohup`. Просится `launchd`-plist или crontab
  (`*/10 * * * * cd /path && ./tools/kvadrat-random.sh once` и
  `*/4 * * * * cd /path && ./tools/kvadrat-visitor.sh once`).
- **Посетители одинаковые по темпу**: сейчас ровно раз в 4 минуты. Живее было бы
  случайное окно (2–6 минут) и иногда пропущенный тик — «никто не подошёл».
- **Бот на проде.** Сейчас всё локально на маке. На сервере нет `sips` — для картинок
  понадобится `apt install imagemagick` (бэкенд `magick` в коде уже предусмотрен), а сам бот
  можно повесить вторым процессом в `deploy/ecosystem.config.cjs`. Для `kvadrat-send.mjs`
  ничего не нужно — он на чистом Node.
- **Урезанная версия.** Ядро («сделать сетку и послать по сокету») — это ~20 строк; остальное
  это фичи (превью, diff, `--animate`, два формата) и защита для работы без присмотра.
  Если объём мешает — можно свести бота и отправку к ~45 строкам, потеряв лок, watchdog,
  антиповтор тем и понятные ошибки.
- **Жанры заданы списком, а не комбинируются.** Сейчас кубик выбирает одну строку из десяти;
  живее было бы собирать промпт из независимых осей (масштаб × композиция × настроение),
  тогда вариантов станут сотни вместо десяти.
